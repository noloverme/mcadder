# MC Adder - Добавление серверов Minecraft

Этот скрипт позволяет массово добавлять или удалять серверы Minecraft в файл `servers.dat`, который хранится в директории вашей игры.

## Возможности

*   **Добавление серверов**: Добавляйте серверы из текстового файла.
*   **Удаление серверов**: Удаляйте серверы, перечисленные в файле.
*   **Поддержка разных лаунчеров**: Автоматическое определение путей для стандартного Minecraft, TLauncher и LiquidBounce.
*   **Резервное копирование**: Автоматически создает резервную копию (`servers.dat.bak`) перед внесением любых изменений.
*   **Интерактивный интерфейс**: Удобное меню для выбора действий.

## Требования

*   Python 3.6+
*   Библиотека: `nbtlib`

## Установка зависимостей

Перед первым запуском установите необходимые библиотеки:

```bash
pip install -r requirements.txt
```

или

```bash
pip install nbtlib
```

## Как пользоваться

1.  **Запустите скрипт**:
    ```bash
    python main.py
    ```

2.  **Выберите директорию Minecraft**:
    Скрипт предложит выбрать одну из стандартных директорий или указать свою.

3.  **Выберите действие**:
    *   **[1] Добавить**: Добавить серверы в `servers.dat`.
    *   **[2] Удалить**: Удалить серверы из `servers.dat`.
    *   **[3] Сканировать**: Пинг host:25000-26000 + пробный вход и добавить.

4.  **Выберите файл списка серверов**:
    *   **[1] Использовать `localips.txt`** (по умолчанию, рядом со скриптом).
    *   **[2] Указать другой файл**.

### Формат файла со списком серверов

Файл должен иметь следующий формат:

*   Каждый сервер на новой строке.
*   Формат строки: `Имя сервера|IP:порт` или просто `IP:порт`.
*   Если имя не указано, будет использован IP-адрес.
*   Строки, начинающиеся с `#`, игнорируются.

**Пример `localips.txt`:**

```
# Это комментарий, он будет проигнорирован
Hypixel|mc.hypixel.net
play.cubecraft.net
Another Server|192.168.1.100:25565
```

После выполнения скрипта серверы будут добавлены или удалены из вашего списка серверов в игре.

### Сканирование (пункт [3])

Для каждой строки `localips.txt` без порта перебираются порты `25000-26000`
(строка с `host:port` сканируется точечно):

1.  SLP-пинг Java-сервера — жив ли.
2.  Если жив — пробный вход со случайным валидным ником (`PlayerXXXXXX`).
3.  Классификация:
    *   `valid` — Login Success, без кика;
    *   `whitelisted` — кик `You are not whitelisted...` / `multiplayer.disconnect.not_whitelisted` (отбрасывается);
    *   `warning` — живой, но кик с другой причиной, `online-mode` (encryption), закрытие соединения и т.п.;
    *   `offline` — нет SLP-ответа (не сохраняется).

Результат сохраняется в `scan_valid.txt` / `scan_warning.txt` в формате `Имя|host:port`,
далее на выбор:

*   **[1]** Очистить свой список и добавить только валидные;
*   **[2]** Добавить только валидные (не очищая);
*   **[3]** Добавить валидные + с предупреждениями;
*   **[4]** Ничего не делать.

Зависимостей не требует (только stdlib: `asyncio`), `nbtlib` нужен как раньше
для записи `servers.dat`. Скан двухфазный: сначала быстрый SLP-пинг всех
целей (дефолт `1000` параллельных, таймаут `2.5с`, DNS резолвится один раз
на хост), затем вход только по живым (до `80` параллельных, таймаут `8с`).
Диапазон портов и concurrency пинга спрашиваются интерактивно
(по умолчанию `25000-26000` и `1000`).

### Прокси (http/socks4/socks5)

При сканировании можно идти напрямую, через один прокси или через список
(round-robin по всем подключениям — и пинг, и вход):

*   Форматы: `socks5://host:port`, `socks5://user:pass@host:port`,
    `http://host:port`, `http://user:pass@host:port`, `socks4://host:port`,
    `socks4a://host:port` (с резолвом через прокси), `https://...`.
    Голый `host:port` считается `socks5`.
*   Файл списка — один прокси на строку, `#` — комментарий, пустые пропускаются:
    ```
    # пример proxies.txt
    socks5://127.0.0.1:1080
    socks5://user:pass@10.0.0.5:1080
    http://10.0.0.6:8080
    ```
*   Перед сканом все прокси проверяются параллельно (туннель до первой цели;
    закрытый порт цели тоже засчитывается — важен ответ самого прокси),
    мёртвые отбрасываются. Во время скана сбой прокси = 1 повтор через
    следующий прокси; после 30 подряд ошибок прокси помечается мёртвым.
    В итоге показывается `Прокси: запросов N, ошибок M, мертвых K`.
*   Замечание: `socks4` без `a` не умеет резолвить имена — тогда хосты
    резолвятся локально один раз на хост; `socks5`/`http`/`socks4a`
    резолвят через прокси. Зависимостей не добавляется, всё на stdlib.
